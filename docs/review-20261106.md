## Dependency and installation findings

1. **The advertised Python range exceeds the full app's range.** `pyproject.toml` permits Python 3.9–3.12, but both application requirements files demand NumPy >=2.5.4. [Published NumPy 2.5.4 metadata](https://pypi.org/pypi/numpy/2.5.4/json) requires Python >=3.12. The Python 3.11 CI succeeds by installing its own subset instead. The main installer correctly selects 3.12; align/document installation profiles and add an installation gate before changing supported-version claims.
2. **Main and RVC must remain isolated.** [rvc-python 0.1.5 metadata](https://pypi.org/pypi/rvc-python/0.1.5/json) pins NumPy <=1.23.5, faiss-cpu==1.7.3, and fairseq==0.12.2. Its NumPy range cannot coexist with the main >=2.5.4 requirement. Separate sidecars already address that conflict; do not combine those requirements.
3. **XTTS and RVC also have incompatible NumPy ranges on Python 3.11.** [TTS 0.22.0 metadata](https://pypi.org/pypi/TTS/0.22.0/json) requires Python <3.12 and NumPy >=1.24.3 on Python >3.10. Isolation is necessary. The main interpreter cannot install that TTS release.
4. **RVC bootstrap has inconsistent compatibility declarations.** The uv path selects Python 3.10, while the non-uv path prefers 3.11 for both sidecars despite the runbook documenting fairseq trouble on 3.11+. The installer bootstraps setuptools <81, but its requirements permit <85. These inconsistencies were observed statically; their exact failures were not reproduced in a real RVC environment here.
5. **Wheel packaging omitted the cloning subpackage.** Built the original main package independently and confirmed its wheel lacked `ai_vocals_studio/voice_cloning`. The review branch fixes discovery; the rebuilt wheel includes the dispatcher and adapters. This does not package the entire repository-root production CLI stack or install missing backend extras.
6. **The new Demucs shim has an uninstalled external dependency.** `demucs_infer/__init__.py` reads `external/demucs-infer/demucs_infer/__init__.py`, but that checkout is ignored and not created by the normal installer. The primary song path instead invokes the installed `demucs` module; that separate path should not be conflated with this shim.

Published required versions were found in PyPI; there is no evidence here that the dependency floors simply reference nonexistent releases. No complete neural-runtime dependency resolution or installation was performed.

## Safe changes implemented on this review branch

- Propagate selected cloning backend failures and reject Silero as a reference clone. A generic voice can no longer silently masquerade as the requested speaker through this dispatcher. Label the separate voice-swap demo as experimental and direct song users to the production CLI. Explicit `model="silero"` calls now raise a documented error.
- Launch the worker using the installer's `.venv`, retain legacy `venv`, support `MAIN_PY`, and allow an explicitly configured local queue. Missing runtime/storage configuration produces an actionable error. `exec` preserves interrupt delivery.
- Remove the npm Dependabot entry for the absent manifest, remove the missing optional label, and ignore Torch/Torchaudio updates >=2.6 until the RVC compatibility boundary is deliberately validated. Existing PRs remain open.
- Include cloning subpackages in built wheels.
- Add behavioral regressions for backend failure, explicit non-cloning backends, path forwarding, and launcher compatibility/failure paths. Update README setup guidance.

Validation on this branch: **111 Python tests passed; 23 Node upload tests passed; Python compilation, shell syntax, `git diff --check`, dependency-config checks and wheel-content verification passed.** Seven new assertions failed against the original implementations before the fixes. A real worker process started against an empty local queue and exited successfully. Full audio rendering and the target VPS remain unverified. No production deployment, merge, paid API call, model training, branch deletion, or job retry was performed.
